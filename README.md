# thermal-equity-data-integrity

Code and derived data for **“Data Integrity and Thermal Equity in Urban Forest
Management: How Illicit Data Markets Distort AI-Assisted Heat Mitigation”**
(Ziying Xue, Yongjin Chen, Songze Zhu — People's Public Security University of
China).

The paper asks what happens to a planting priority list when the labels that
train it are deliberately distorted in one direction. This repository contains
the two pieces of evidence that can be executed:

| Directory | What it is | Runnable without private data |
|---|---|---|
| `synthetic/` | 600-cell synthetic city, 30 seeds, directional vs random label contamination. Produces **Figure S1** and **Table S1** of the paper. | **Yes** — bit-for-bit, see `synthetic/CHECKSUMS.txt` |
| `nanjing/` | The 1-km grid pipeline for the Nanjing experiment (**Section 4.4**, **Table 2**, **Figures 3–4**): raster ingestion, random-forest priority model, label contamination, metrics, figures. | Code runs; inputs are two public datasets, listed in `nanjing/README.md` |

## Quick start

```bash
pip install -r requirements.txt      # or: conda env create -f environment.yml

python run.py synthetic   # regenerates the synthetic results and verifies checksums (~3 min)
python run.py test        # end-to-end smoke test of the Nanjing pipeline on tiny rasters
python run.py nanjing     # needs LST/RED/NIR/POP paths, see below
```

`run.py` is the canonical entry point because `make` is not installed by
default on Windows. The `Makefile` wraps the same commands for POSIX users; it
is a convenience, not a second implementation.

For the Nanjing run, download the inputs described in `nanjing/README.md`, then:

```bash
export LST=.../LC08_L2SP_120038_20210801_02_T1_ST_B10.TIF
export RED=.../LC08_L2SP_120038_20210801_02_T1_SR_B4.TIF
export NIR=.../LC08_L2SP_120038_20210801_02_T1_SR_B5.TIF
export POP=.../GHS_POP_E2020_GLOBE_R2023A_4326_30ss_V1_0.tif
python run.py nanjing
```

`nanjing/find_scene.py` prints the metadata of the Landsat scene the paper
means (scene id, path/row, acquisition time, cloud cover, asset paths) from the
public STAC endpoint, so the identification can be checked without downloading
anything. The saved response is `nanjing/scene_metadata.json`.

Outputs land in `nanjing/outputs/`: `cells.csv` (one row per analysis cell),
`conditions.csv` (one row per condition — the object compared with Table 2),
`run_metadata.json`, `Figure_3.png`, `Figure_4.png`.

## What is and is not in this repository

- **Included:** all analysis code, the synthetic results, and the metadata
  needed to rerun both experiments.
- **Not included:** the raw satellite and population rasters (large, and
  better obtained from the providers) and the Nanjing cell-level table
  (`cells.csv`), which is regenerated by `make nanjing`. It is not committed
  because it is an output of public inputs, not an input.
- The manuscript reports **N = 644** analysis cells and **N = 141** vulnerable
  cells. The count your run produces is printed by `build_grid.py` and
  `model_and_poison.py`; it depends on the built-up mask and on how many cells
  survive the missing-data filter. If it differs from 644, the mask differs,
  not the code.

## Reproducibility notes

- The random forest is fitted with `n_jobs = 1`. Parallel prediction
  accumulates in completion order, which changes the last digits of the
  predicted values and therefore the CSVs. This is the one setting that makes
  “fixed seed” mean “identical file”; do not change it.
- The synthetic pipeline is verified by re-running it twice and comparing
  byte-for-byte; `synthetic/CHECKSUMS.txt` holds the MD5 sums of the three CSVs
  that the manuscript's Supplementary Table S1 is built from. `python run.py
  checksums` verifies them in place.
- Those CSVs are written with `lineterminator="\n"` so the MD5 sums do not
  depend on the operating system, and `.gitattributes` marks them `-text` so
  git never rewrites them on checkout.
- `Figure_S1.png` is regenerated by the same run and came out byte-identical to
  the figure in the Supplementary Materials on the machine where this was
  checked; it is not covered by `CHECKSUMS.txt`, because PNG bytes depend on
  the matplotlib and freetype versions.
- `python run.py test` exercises the full Nanjing path on a 40 × 40 synthetic
  raster stack, so the code is testable without downloading anything. It checks
  the schema and the direction of the effect, not the manuscript's values — the
  test data are synthetic.
- The Nanjing numbers in the paper come from the authors' analysis of these
  inputs; the repository contains the code and the scene identification, not a
  stored result table. The smoke test shows that the code runs end to end, not
  that a given machine reproduces Table 2 — that depends on the built-up mask,
  the retained cell count and the estimator settings listed above.

## Data sources

- Landsat 8 Collection 2 Level-2, scene **LC08_L2SP_120038_20210801_02_T1**
  (WRS-2 path 120, row 038; acquired 1 August 2021; scene cloud cover 12.86%).
  Available from USGS EarthExplorer and from the public STAC endpoint used to
  identify the scene (`earth-search.aws.element84.com/v1`).
- **GHS-POP R2023A** (GHS population grid, 2020 epoch, 30 arc-seconds),
  European Commission Joint Research Centre, <https://ghsl.jrc.ec.europa.eu>.
- Optional: **GHS-BUILT-S R2023A** for the built-up mask.

## Caveats

The Nanjing experiment covers one city on one date and models a single
contamination path (training labels). It does not estimate how often such
contamination occurs, nor the temperature consequences of a reallocation.
Those limits are stated in Section 6.3 of the paper and should be kept with
any reuse of these results.
